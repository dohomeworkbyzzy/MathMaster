# 变限积分与未知函数偏导

原报错源于 AI 将 `integrate(...)` 交给只认识初等表达式的求导器。此外，旧语法不认识撇号，且会把 `u(x+y)` 误读成 `u*(x+y)`。

现在支持封闭的符号表达式：

- `integrate(phi(t)+phi(-t),(t,x-y,x+y))`：有限端点的一重定积分，保留未知被积函数，按 Leibniz 公式求导。
- `phi'(x+y)`、`phi''(x+y)`：一元未知函数的形式导数；`phi`、`varphi`、`φ`、`ϕ` 是同一函数的记号。
- `variables=["x","y"]`：先对 x 再对 y 求偏导；支持至多八阶。
- 默认未知函数名为 f/g/h/u/v/w/phi/varphi；其他函数名在 `functions` 声明。乘法明确写作 `u*(x+y)`。
- `math.check_derivative`：从原函数计算指定导数，再核对用户的式子。未编码额外函数约束时，可用光滑多项式反例否定不成立的恒等式；找不到反例不代表相等。

“如果我的导数正确再计算其余项”是有条件的委托。系统先执行核验；不通过或无法确认时不执行其余项，也不接受模型自行改写用户的式子后绕过这一条件。偏导类型不明确时，AI 应先确认当前在核对哪个偏导。

没有更换为任意 Python/SymPy 字符串执行。语法仍逐词元解析，积分、未知函数和 diff 仅通过固定构造器创建，保留长度、深度、词元、阶数和工作进程资源限制。工具缓存版本已更新，避免命中旧解析方式产生的结果。

数学检查覆盖原题的四个二阶偏导、负自变量符号、只需 phi 一阶导数、已知多项式实例、错误表达式的反例、符号结果再次解析、工具进程和有条件委托顺序。已有初等微积分与 AI 回归继续运行。

Windows 服务器使用 `master-calculus-update.exe` 更新完整运行程序，选择原含 master.exe 的目录。数据、设置、难度推荐、草稿和触摸板功能保留。

## 同链路补充修复

- 多元复合函数连续求偏导改为保留自变量位置的形式节点，避免底层 CAS 在 `f(x,x)`、`f(x²,y²)` 中混淆位置或留下不可解析的内部占位符。`partial(f(x,y),1,2)` 表示先对第一、再对第二自变量求偏导；在相应连续可微条件下合并混合偏导。结果可继续核验、代入和求导。
- 支持 `\varphi^{\prime}(x)`、`f^{\prime\prime}(x)` 等常用上标撇号。
- 未能显式积分的不定积分结果使用 `integrate(phi(x),x)`，可以重新解析并求导；多重积分按嵌套构造器输出。
- 自定义未知函数声明会传给代入值解析器，不再在跨工具代入时丢失。
- 截断积分／偏导表达式及异常函数声明统一给出数学输入错误，保留封闭语法和资源限制。
- “检查我的导数”本身即可授权当前核验；“核验通过后再算”与跨行条件也受先检查后计算的限制。失败后的停止指令保留至下一轮模型反馈。
- 电脑与手机的核验卡片显示核验通过、不通过或无法确认，区分参考导数与用户提交式，并显示合法反例及适用条件。

新增多元偏导验证使用具体二元多项式独立求导作为对照，包括重复自变量与结果再次求导；解析器另运行 1500 条固定随机种子的短畸形表达式检查，未出现未捕获的输入异常。Windows 冻结运行验证覆盖原题、以上新增符号语法和真实 HTTP 接口。未将这些离线／本地检查表述为所有模型或用户现场均已验收。

复杂导数核验直接使用已计算的内部符号表达式，避免展开后的长公式被当作新输入再次解析、误触发输入长度或词元上限。用户输入仍受原限制；过长的结果需要分项继续计算。额外覆盖三元未知函数和复杂展开结果核验。
