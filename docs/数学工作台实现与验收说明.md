# MathMaster 实现与验收说明

## 实际交付范围

从空目录初始化完整系统。第一阶段的积分、求导、矩阵/行列式、步骤展示和 SQLite 记录保存已编码；第二、三阶段继续交付本地试卷导入、人工校对、题库、三栏练习、答案/笔记/草稿保存、错题本和继续作答。

这是一版本地最小闭环，并不宣称所有试卷版式自动拆分和所有数学函数推导已经覆盖。产品没有模拟 API、虚假计算结果或空的排行榜/AI 批改入口。

## 数学引擎

积分同时使用 SymPy 的 integrate、manualintegrate、integral_steps。依据当前 1.14 的 dataclass Rule 结构实现 JSON 步骤适配，而非复制旧 Gamma HTML 输出。

研究参考：

- [SymPy Gamma intsteps.py](https://github.com/sympy/sympy_gamma/blob/master/app/logic/intsteps.py)
- [SymPy Gamma diffsteps.py](https://github.com/sympy/sympy_gamma/blob/master/app/logic/diffsteps.py)
- [SymPy 积分文档](https://docs.sympy.org/latest/modules/integrals/integrals.html)
- [MathLive 本地打包说明](https://mathlive.io/mathfield/guides/integration/)

旧 Gamma 使用 context、_manualintegrate、evaluates、namedtuple 等结构，当前 SymPy 使用 integrand、variable 和 rule.eval()；新代码没有 monkey-patch SymPy，也没有共享全局“正在积分”的变量。常数规则的子树元数据可能携带未缩放 integrand，新适配器使用父级真实操作数，并对关系逐步验证，避免误读旧上下文。

已覆盖换元、分部、逐项、提出常数、部分分式/恒等变形及常见基本公式。未知规则仅返回经验证的结果，steps_complete=false，中文警告明确告诉用户缺少详细推导。

不定积分显示 C；实数对数原函数的 ln|g| 转换验证正负连通区间的导数一致性，说明原函数可相差常数，并列出定义域与非零条件。

定积分要求明确实数或无穷上下限。先检查原始表达式实数定义域与奇点，在内部奇点处分段，并独立计算原函数的单侧极限。每段都收敛才相加；1/x 在 [-1,1] 不会以主值 0 冒充积分。无法可靠判断定义域、枚举奇点或完成验证时拒绝或明确显示未验证状态。该保守策略会拒绝部分 SymPy 能处理但本模块无法安全判断的复杂区间。

求导参考 Gamma 的求导规则树结构，独立构造链式、乘积、商、幂、基本函数与逐项规则，递归生成子步骤，再与 SymPy diff 核验。支持高阶及指定变量序列的偏导。未适配结构明确降级。

## 独立矩阵步骤引擎

RowEngine 用精确有理数实现主元选择、交换、倍乘和倍加，支持行最简形、秩、上三角行列式和 [A|I] 求逆；增广矩阵在公式中显示分隔线。每步记录行号、系数、前后矩阵、数学意义和行列式乘数。方阵逐步核验 determinant(after)=multiplier*determinant(before)。

行列式另有递归余子式按行展开法；求逆检查 A*inverse=I；线性方程组回代验证 A*x=b，处理矛盾行和自由变量。结果与 SymPy det/rref/rank/inv/linsolve 交叉验证。含符号主元时采用一般参数分支并显式列出非零条件；没有伪装成全参数分类。

## 数据结构与 API

结果公共字段：operation、input_latex、result_latex、exact_result、approximate_result、method、assumptions、steps、verified、warnings。另含 steps_complete、history_id、created_at、question_id 与相关 status。

每步：step_id、rule、before_latex、after_latex、explanation_zh、children；额外提供 verified、verification 证据，以及可用的 formula_latex、choices_latex 和行操作结构。

verified 表示列出条件下的数学结果验证；steps_complete 表示展示规则是否完整，两者独立，不能因“答案正确”宣称“推导完整”。

```text

POST /api/math/matrix
GET  /api/math/history
POST /api/papers/import
GET  /api/papers
GET/POST /api/questions
GET/PUT  /api/questions/{id}
```

API 文档在 http://127.0.0.1:8765/docs。计算请求可带 question_id，不填写则属于独立工作台。插入笔记时校验记录必须属于当前题目，防止跨题混写。

SQLite 启用 WAL、外键和事务。作答保存提供 expected_updated_at 乐观锁；多个窗口使用旧版本写入时返回 409，并保留本机草稿。每次写入串行排队，切题等待保存。浏览器草稿使用窗口标识隔离并保留基础记录版本；恢复旧草稿前检查版本，不自动覆盖数据库新笔记。备份使用 SQLite backup API，包含原始文件与全部截图。

## 输入与进程隔离

生产数学路径没有 eval、exec、parse_expr 或 sympify(用户字符串)。自研词法 + Pratt 解析器只允许数学运算、常数、单字母变量与白名单函数；受限 LaTeX 读取器完整消费输入，拒绝未识别命令或不完整结构。

限制：600 字符、160 词元、24 层嵌套、120 运算节点、数值指数范围、8 阶导数、8×8 矩阵。每个计算使用新的 Python 工作进程，通过 JSON stdin/stdout 传输，不使用 pickle；最多同时两项，默认 15 秒超时后 kill + wait。Linux 另设 CPU 与地址空间限制。Windows 通过独立进程与强制终止提供超时隔离，没有宣称提供 OS 级完整沙箱或 Job Object 内存配额。

试卷解析也在独立进程运行，单次最多 30 MB/80 页，DOCX 先限制 ZIP 展开体积；超时终止进程树。原文件名称内部换成随机目录及固定 source 名，截图访问检查路径，防止遍历。服务只绑定 127.0.0.1，并检查 Host/Origin，前端 KaTeX 关闭 trust。

## 当前限制及后续工作

- 复杂双栏试卷、重复小题题号、表格/插图关联和页眉页脚仍需人工校对。题号规则只是候选拆题。
- 没有可靠的数学公式 OCR；扫描文本仅草稿，发送计算器必须明确确认。
- 原版式 DOCX 截图需要 LibreOffice；无转换器时文字、表格与内嵌图片仍可导入，但 Office 公式仅保留原始片段，建议另存 PDF。
- 尚无完整符号参数分支穷举、隐函数求导、任意 LaTeX 语法或所有 SymPy 积分规则中文适配。
- 默认单用户、单台电脑使用；没有云同步或多用户权限系统。
- Windows 安装依赖与实际工作进程需本机核查；测试结论见下方，不把 WSL 的测试等同于 Windows 全部验收。
