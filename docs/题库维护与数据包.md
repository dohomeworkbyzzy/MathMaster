# 题库维护与数据包

服务器上继续使用现有的 master 目录。维护工具是独立的 Windows 程序，无需安装 Python 或 Node.js。

## 本次升级

1. 将 `master-maintenance-kit.zip` 复制到服务器并解压到一个单独的目录。
2. 双击 `master-maintenance.exe`，选择服务器上 **现有 master.exe 所在目录**。
3. 选择 `master-program-update.zip`，点击“开始更新”，等到成功。
4. 在同一个工具中选择 `master-408-data.zip`，再次点击“开始更新”，等到成功。
5. 浏览器按 Ctrl+F5 刷新，在题库中选择 408 和对应做题本。

程序包升级前后端运行环境；本次题库包增量导入原题、截图和选择题参考选项。先升级程序，才能使用本次 JPEG 题图。工具会检查程序包要求，顺序不符时提示先升级程序。

无需替换服务器的整个 data 目录。服务器和维护工具应在同一个 Windows 登录会话内运行。维护期间会短暂停止该目录的服务，成功后自动启动并检查页面。

## 答案与原图

原 PDF 和每题截图都会保留，OCR 文字仅作辅助。参考答案标注“AI 生成，待核对”，不是原书或官方答案。不确定、遮挡、缺字或无法可靠解出的题目保留生成说明，暂不自动判分，列在 `needs-review.csv` 中。

多空选择题保留为一个题干，选项按各空顺序列出；其输入采用文本形式。普通单选题可以用 A/B/C/D 作答。

## 备份与重复维护

每次维护在 `<master目录>/.updates/` 下保存数据库和配置备份。程序升级另保存旧运行文件；题库升级不替换数据库文件。

已有题目、用户、答题记录、草稿、标注和 API 设置保留。相同 ID 的题目再次入库时跳过；只有题干与图片完全相同、原答案仍为空的题目才会补齐空答案。已编辑的答案和题干不覆盖。

题库导入及导入回执在一个事务内提交，附件不覆盖已有不同内容的文件。包损坏、路径异常或附件冲突在停止服务前检查；入库异常回滚事务。题库导入后启动检查失败，会停止服务并从本次快照恢复题库。备份包含私人配置，请自行保管。

## 下次生成数据包

继续使用同一个工具，在开发机准备审核过的 `import-plan.json` 和所引用的原 PDF/图片，执行：

```bash
python scripts/build_library_package.py --plan path/to/import-plan.json --uploads data/uploads --output artifacts/master-new-data.zip
```

计划中只需要 `papers`、`questions` 两组共享题库数据。格式可参考本次 `artifacts/408-workbooks/import-plan-answers.json`；每题须有稳定 ID、关联试卷、题干、图片、参考答案和评分 spec。无答案可以保留空字符串，之后通过新包补齐。原图路径相对 uploads，所有被引用的文件必须存在。

生成的数据包自带文件清单、SHA256 和导入计划，不包含学习记录、数据库、模型文件或 API 密钥。把新 ZIP 交给同一个维护工具导入即可。如果只增补题库，无需重新编译维护工具或重装客户端。

程序更新使用 `scripts/build_server_update.py` 生成的 `master-release-*.zip`，同样在维护工具中选择。独立维护工具可用原生 Windows Python 执行 `scripts/build_maintenance_tool.py` 重建。

## 开发验收

- `tests/test_library_update.py`：增量导入、重复导入、空答案补齐、修改保留、事务回滚、路径和附件完整性。
- `tests/test_library_files.py`：PNG/JPEG/WebP 原图服务和受限文件访问。
- `scripts/check_library_maintenance.py`：独立 Windows 运行文件，真实启动/停止/重启、图片及答案读取、双用户记录保留、备份、重复维护、启动失败恢复。
- `scripts/check_server_update.py`：真实前后端程序更新、旧记录保留和失败回退。

上述检查在隔离副本执行。远端生产服务器上的实际维护需将包复制过去后执行。
